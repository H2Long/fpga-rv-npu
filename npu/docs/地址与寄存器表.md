# NPU v2.1 地址与寄存器表

本文档描述当前 `npu_system` 的 CPU MMIO 地址空间、控制寄存器、状态寄存器和三块片上 Buffer。

## 1. CPU MMIO 接口

```text
cpu_addr[31:0]
cpu_wdata[31:0]
cpu_byte_en[3:0]
cpu_we
cpu_valid
cpu_rdata[31:0]
cpu_ready
```

地址按字节寻址，32 位访问通常按 4 字节对齐。

一次访问的基本流程：

```text
cpu_valid=1
    -> mmio_if 锁存请求
    -> 目标寄存器或 Buffer 执行访问
    -> cpu_ready=1 一个时钟周期
```

CPU 检测到 `cpu_ready=1` 后，应撤销当前 `cpu_valid`，避免同一请求被再次采样。

## 2. 地址空间总览

| 地址范围 | 类型 | 大小 | 说明 |
|---|---|---:|---|
| `0x0000_0000 ~ 0x0000_001F` | 控制寄存器 | 32 B | 配置参数和启动命令 |
| `0x0000_0020 ~ 0x0000_002F` | 状态寄存器 | 16 B | 运行状态 |
| `0x0000_1000 ~ 0x0000_10FF` | A Buffer 窗口 | 256 B | 64 个 32 位字 |
| `0x0000_2000 ~ 0x0000_20FF` | BT Buffer 窗口 | 256 B | 64 个 32 位字 |
| `0x0000_3000 ~ 0x0000_33FF` | C Buffer 窗口 | 1 KB | 256 个 32 位字 |

未列出的地址属于保留地址，读回 0，写入被忽略。

## 3. 控制寄存器

### 3.1 `CTRL`：启动和完成清除

地址：`0x0000_0000`

| 位 | 名称 | 读写 | 复位/读值 | 说明 |
|---:|---|---|---:|---|
| 0 | `start` | W | 0 | 写 1 启动一次任务 |
| 1 | `clear_done` | W | 0 | 写 1 清除 DONE / ERROR 状态 |
| 31:2 | 保留 | - | 0 | 写入无效 |

`CTRL` 是命令寄存器，不保存 bit0/bit1。读取 `0x0000` 始终返回 0。

常用写值：

```text
0x0000_0001：启动任务
0x0000_0002：清除 DONE / ERROR
0x0000_0003：同时请求启动和清除
```

`DONE=1` 时再写 `start` 是合法的：新任务直接启动并把 DONE 清掉，
软件不需要"先写 clear_done 再写 start"。配置非法时写 `start` 不会启动任务，
而是把 `STATUS.ERROR` 置 1（见 §4.2）。

### 3.2 `M_CFG`：矩阵行数

地址：`0x0000_0004`

| 位 | 名称 | 读写 | 复位值 | 有效范围 |
|---:|---|---|---:|---:|
| 5:0 | `M` | R/W | 4 | 1~63，且满足 §4.3 的容量约束 |
| 31:6 | 保留 | - | 0 | - |

### 3.3 `N_CFG`：矩阵列数

地址：`0x0000_0008`

| 位 | 名称 | 读写 | 复位值 | 有效范围 |
|---:|---|---|---:|---:|
| 5:0 | `N` | R/W | 4 | 1~63，且满足 §4.3 的容量约束 |
| 31:6 | 保留 | - | 0 | - |

### 3.4 `K_CFG`：内积长度

地址：`0x0000_000C`

| 位 | 名称 | 读写 | 复位值 | 有效范围 |
|---:|---|---|---:|---:|
| 5:0 | `K` | R/W | 4 | 1~63，且满足 §4.3 的容量约束 |
| 31:6 | 保留 | - | 0 | - |

### 3.5 `ACC_CFG`：跨任务累加

地址：`0x0000_0010`

| 位 | 名称 | 读写 | 复位值 | 说明 |
|---:|---|---|---:|---|
| 0 | `accumulate` | R/W | 0 | 1：本次任务的 C 结果**加到** C Buffer 原值上；0：覆盖写入 |
| 31:1 | 保留 | - | 0 | - |

用于把 K 维分段装载、用多次任务累加出完整部分和：

```text
段 1：装载 K 段 1 的 A/BT，K=K1，accumulate=0，start   -> C = 段 1 部分和
段 2：装载 K 段 2 的 A/BT，K=K2，accumulate=1，start   -> C = 段 1 + 段 2
...
```

约束：`accumulate=1` 时每段写入的是**未量化的原始部分和**，所以要求
`QUANT_CFG.qshift=0`；同时置位会被判为非法配置（`STATUS.ERROR=1`），
避免"设置了量化却被静默忽略"。分段累加完成后由软件自己做量化。

### 3.6 `TK_CFG`：K 方向 Tile 大小

地址：`0x0000_0018`

| 位 | 名称 | 读写 | 复位值 | 有效范围 |
|---:|---|---|---:|---:|
| 4:0 | `TK` | R/W | 4 | 1~16 |
| 31:5 | 保留 | - | 0 | - |

`TK` 只影响内部流水长度和 FIFO 占用，**不再是性能参数**：K Tile 之间不清累加器、
不排空阵列，而且下一个 K Tile 的预取与当前喂数重叠，所以 TK 取 2~16 的性能差别在
15% 以内（见设计说明 §6）。

### 3.7 `QUANT_CFG`：量化右移位数

地址：`0x0000_001C`

| 位 | 名称 | 读写 | 复位值 | 说明 |
|---:|---|---|---:|---|
| 4:0 | `qshift` | R/W | 0 | 结果右移位数，0 表示不右移；负数按四舍五入右移，结果饱和到有符号 32 位 |
| 31:5 | 保留 | - | 0 | - |

## 4. 状态寄存器

### 4.1 `STATUS`

地址：`0x0000_0020`

| 位 | 名称 | 读写 | 含义 |
|---:|---|---|---|
| 0 | `BUSY` | R | `1`：NPU 正在执行任务 |
| 1 | `DONE` | R | `1`：任务完成，可读取 C Buffer |
| 2 | 保留 | R | 固定为 0 |
| 3 | `BUFFER_READY` | R | `1`：CPU 可以访问 Buffer |
| 4 | `ERROR` | R | `1`：上一次 `start` 的配置非法，任务未启动 |
| 31:5 | 保留 | R | 读为 0 |

推荐判断顺序：

```text
轮询 STATUS，直到 BUSY=0
若 ERROR=1 -> 修正配置，写 CTRL.clear_done，重新 start
若 DONE=1 -> 读取 C Buffer
```

地址 `0x0000_0024` 保留，读取为 0。

### 4.2 `ERROR` 的语义

`ERROR=1` 表示"启动被拒绝"，此时核心完全空闲（`BUSY=0`），不会锁死：
软件写 `CTRL.clear_done` 即回到空闲，可以修正配置后重新启动。

会置 `ERROR` 的情况见 §4.3 和 §3.5。

### 4.3 配置合法性（启动时校验）

`start` 会在启动瞬间校验配置，任一条不满足就拒绝启动并置 `ERROR`：

```text
M、N、K 均不为 0
TK 在 1..16
ceil(M/4) * K <= 64      (A Buffer 只有 64 个 32 位字)
ceil(N/4) * K <= 64      (BT Buffer 只有 64 个 32 位字)
M * N <= 256             (C Buffer 只有 256 个 32 位字)
accumulate=1 时 qshift 必须为 0
```

**注意**：寄存器位宽给出的 1~63 只是上界，真正的约束是 Buffer 容量。
例如 `K=63` 时 `M` 最多为 4（`ceil(4/4)*63 = 63 <= 64`），
`K=32` 时 `M` 最多为 8，而单个任务的最大规模是 `16x16x16`（此时 A/BT 各用满 64 字）。

## 5. A Buffer

地址窗口：`0x0000_1000 ~ 0x0000_10FF`

实际有效存储为 64 个 32 位字：

```text
有效地址：0x1000 + 4*i，i=0..63
内部字地址：(CPU地址 - 0x1000) >> 2
```

一个 32 位字的打包格式：

| 位段 | 内容 |
|---|---|
| `[7:0]` | A lane 0 |
| `[15:8]` | A lane 1 |
| `[23:16]` | A lane 2 |
| `[31:24]` | A lane 3 |

数据按 K 主序存放。对于一个 A Tile，地址基准为：

```text
A 字基址 = tile_i * K + tile_k * TK
```

## 6. BT Buffer

地址窗口：`0x0000_2000 ~ 0x0000_20FF`

实际有效存储为 64 个 32 位字：

```text
有效地址：0x2000 + 4*i，i=0..63
内部字地址：(CPU地址 - 0x2000) >> 2
```

BT 是 B 的转置矩阵，一个字的打包格式为：

| 位段 | 内容 |
|---|---|
| `[7:0]` | BT lane 0 |
| `[15:8]` | BT lane 1 |
| `[23:16]` | BT lane 2 |
| `[31:24]` | BT lane 3 |

BT Tile 地址基准为：

```text
BT 字基址 = tile_j * K + tile_k * TK
```

## 7. C Buffer

地址窗口：`0x0000_3000 ~ 0x0000_33FF`

实际有效存储为 256 个 32 位字：

```text
有效地址：0x3000 + 4*i，i=0..255
内部字地址：(CPU地址 - 0x3000) >> 2
```

每个字保存一个量化后的 C 元素，按行主序排列：

```text
C 字地址 = C_base + row * N + col
C_base   = tile_i * 4 * N + tile_j * 4
```

边界 Tile 中越界的 C 元素不会写入 C Buffer。
`accumulate=1` 时写入的是 C Buffer 原值加上本段部分和。

## 8. CPU 访问限制

| 条件 | A/BT/C Buffer 访问 |
|---|---|
| `BUSY=0` | CPU 可读写 |
| `BUSY=1` | CPU Buffer 端口被屏蔽，但 MMIO 仍会正常应答（`cpu_ready=1`）|

**注意**：`BUSY=1` 期间对 Buffer 的写请求会被丢弃，而 `cpu_ready` 仍然拉高。
软件必须先确认 `BUSY=0` 再访问 Buffer；硬件不提供"写被丢弃"的错误上报。

## 9. 推荐软件访问顺序

```text
1. 确认 STATUS.BUSY=0
2. 写 A Buffer / BT Buffer
3. 写 M_CFG/N_CFG/K_CFG
4. 写 TK_CFG / QUANT_CFG / ACC_CFG
5. 写 CTRL.start=1
6. 轮询 STATUS：BUSY 变 0 后检查 ERROR / DONE
7. DONE=1 时读取 C Buffer
8. （可选）写 CTRL.clear_done=1 清 DONE；直接写 start 启动下一个任务也可以
```
