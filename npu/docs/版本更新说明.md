# NPU v2.0 版本更新说明

版本：`v2.0`  
日期：`2026-09-30`  
范围：`rtl/`、设计说明、波形调试说明和架构绘图脚本

## 1. 版本目标

v2.0 面向课程设计和后续迭代，重点是减少重复包装层、缩短控制信号路径、提高 A/BT/C 通道的复用率。计算功能、MMIO 地址映射和顶层 CPU 接口保持不变。

本版本的结构原则是：

```text
有独立时序或握手协议的模块保留；
纯组合译码、同构包装和恒等映射直接合并到所属功能平面。
```

## 2. 模块变化

### 2.1 顶层控制平面

| v1.x 模块 | v2.0 处理方式 | 变化原因 |
|---|---|---|
| `addr_decoder` | 合并到 `npu_top` | 纯组合地址译码，不需要独立层级 |
| `status_regs` | 合并到 `npu_top` | 只有一个状态读数据 mux |
| `cpu_port_ctrl` | 合并到 `buffer_access_ctrl` | 仲裁、地址、字节屏蔽和 RAM 端口一次完成 |
| `mmio_if` | 保留 | 保存请求生命周期和同步 RAM 读等待状态 |
| `control_regs` | 保留 | 保存软件配置和命令寄存器 |
| `start_ctrl` | 保留 | 保存任务生命周期和参数快照 |

当前 `npu_top` 的控制层为：

```text
mmio_if
control_regs
start_ctrl
buffer_access_ctrl
内联：地址译码、状态读回
```

### 2.2 调度与控制平面

| v1.x 模块 | v2.0 处理方式 | 变化原因 |
|---|---|---|
| `tile_param_latch` | 合并到 `npu_ctrl` 参数复用 | `start_ctrl` 已经锁存任务参数，避免重复寄存器 |
| `config_checker` | 合并到 `npu_ctrl` | 检查逻辑只服务于主 FSM |
| `loop_counters_tile_status` | 合并到 `npu_ctrl` | Tile 数量、边界尺寸直接在调度中心派生 |
| `block_addr_gen` | 合并到 `npu_ctrl` | A/BT/C 地址与 Tile 状态天然相关 |
| `array_ctrl` | 合并到 `npu_ctrl` | 只是 FSM 阶段信号的组合译码 |
| `a_stream_ctrl`、`bt_stream_ctrl` | 直接复用两个 `npu_stream_ctrl` 实例 | 两个通道的逻辑完全相同 |
| `systolic_fsm` | 保留 | 负责完整计算阶段状态转移 |
| `tile_scheduler` | 保留 | 负责 `tile_i/tile_j/tile_k` 的有状态循环 |
| `pair_stream_ctrl` | 保留 | 保证 A/BT 同拍出队和 K 序号一致 |
| `c_tile_acc_ctrl` | 保留 | 负责多 K-tile 部分和累加 |
| `c_tile_write_ctrl` | 保留 | 负责边界过滤、C 地址和写请求 |
| `done_ctrl` | 保留 | 统计真正落入 C RAM 的写操作 |

### 2.3 Buffer 与搬运平面

| v1.x 模块 | v2.0 处理方式 | 变化原因 |
|---|---|---|
| `a_buffer`、`bt_buffer`、`c_buffer` | `npu_buffer` 直接实例化 `npu_ram` | 三块存储只有地址宽度不同 |
| `a_prefetch_fifo`、`bt_prefetch_fifo` | `npu_buffer` 直接实例化 `npu_sync_fifo` | 两个 FIFO 数据宽度和行为相同 |
| `npu_read_port_ctrl` | 内联到 `npu_buffer` | 只保存 A/BT 读使能的一拍延迟 |
| `c_write_fifo` | 保留 | 除 FIFO 外还负责 C RAM 写脉冲和 `c_wr_pulse` |

### 2.4 MAC 平面

| v1.x 模块 | v2.0 处理方式 | 变化原因 |
|---|---|---|
| `a_input_unpacker`、`bt_input_unpacker` | 合并为通用 `input_unpacker` | A 和 BT 的拆包、补零规则相同 |
| `output_reorder` | 删除，`scan_index` 直接作为结果索引 | 当前 collector 已按行主序扫描 |
| `mac_status` | 删除，`collect_done` 直接作为 `array_done` | 原模块只有一拍直通寄存器 |
| `a_bt_skew_pipeline` | 保留 | 负责行/列波前延迟 |
| `pe_array`、`pe_cell` | 保留 | 构成实际 4x4 脉动计算阵列 |
| `drain_controller` | 保留 | 负责阵列排空计数 |
| `tile_result_collector` | 保留 | 串行输出 16 个 PE 累加结果 |
| `result_quantizer` | 保留 | 负责右移、舍入和饱和 |

## 3. 信号线变化

### 3.1 保持不变的外部接口

`npu_system` 的 CPU 接口保持不变：

```text
clk, rst
cpu_addr[31:0], cpu_wdata[31:0], cpu_byte_en[3:0]
cpu_we, cpu_valid, cpu_rdata[31:0], cpu_ready
```

`npu_top` 与 `npu_ctrl` 的任务级接口保持不变：

```text
start_pulse
cfg_m/cfg_n/cfg_k
cfg_tm/cfg_tn/cfg_tk/cfg_qshift
core_busy/core_done/error_code
```

`npu_ctrl`、`npu_buffer`、`npu_mac` 之间的主数据接口也保持不变，已有测试台不需要修改。

### 3.2 删除的信号

```text
feed_last
```

`feed_last` 原来由 `systolic_fsm` 产生，但 `array_ctrl` 不使用它；排空实际由 `drain_en` 控制。

```text
c_result_index_w
array_done_w
```

现在：

```text
c_result_index = scan_index
array_done     = collect_done
```

```text
cpu_buf_wdata
cpu_buf_byte_en
ram_a_*
ram_bt_*
ram_c_*
```

这些中间线由 `buffer_access_ctrl` 合并为直接输出：

```text
cpu_a_addr/cpu_a_we/cpu_a_re/cpu_a_wdata
cpu_bt_addr/cpu_bt_we/cpu_bt_re/cpu_bt_wdata
cpu_c_addr/cpu_c_we/cpu_c_re/cpu_c_wdata
```

### 3.3 新的内部信号归属

同步 RAM 读延迟现在属于 `npu_buffer`：

```text
npu_a_re  -> a_re_d  -> a_fifo_push
npu_bt_re -> bt_re_d -> bt_fifo_push
```

这样 RAM、读延迟和预取 FIFO 在同一模块内完成，数据有效时序更容易追踪。

## 4. 当前数据流向

### 4.1 CPU 装载数据

```text
CPU MMIO
  │ cpu_addr/cpu_wdata/cpu_we/cpu_valid
  ▼
mmio_if
  │ req_addr/req_wdata/req_we/req_valid
  ▼
npu_top 内联译码
  ├── 控制窗口 -> control_regs
  ├── 状态窗口 -> status_rdata
  └── Buffer窗口 -> buffer_access_ctrl
                         │ 地址/读写/字节屏蔽
                         ▼
                      npu_buffer
                         ├── A RAM
                         ├── BT RAM
                         └── C RAM
```

### 4.2 A/BT 输入数据

```text
tile_scheduler + npu_ctrl 地址计算
  │ a_addr/a_re, bt_addr/bt_re
  ▼
npu_buffer.npu_ram
  │ 同步 RAM 数据
  ▼
npu_buffer 内部读延迟
  │ a_fifo_push/bt_fifo_push
  ▼
A/BT npu_sync_fifo
  │ a_fifo_valid/rdata/count
  │ bt_fifo_valid/rdata/count
  ▼
pair_stream_ctrl
  │ a_stream_data + bt_stream_data
  │ pair_fire
  ▼
npu_mac
```

### 4.3 MAC 计算数据

```text
32 位 A/BT 字
  ▼
input_unpacker(A/BT)
  │ 4 个 INT8 lane + lane valid
  ▼
a_bt_skew_pipeline
  │ 行/列波前对齐
  ▼
4x4 pe_array
  │ 每个 PE 累加 32 位部分和
  ▼
drain_controller + tile_result_collector
  │ c_result/c_result_index/c_result_valid
  ▼
c_tile_acc_ctrl
  │ 首个 K-tile 装入，后续 K-tile 累加
  ▼
result_quantizer
```

### 4.4 C 写回数据

```text
c_tile_write_ctrl
  │ cwr_valid/cwr_addr/cwr_data
  ▼
c_write_fifo
  │ ram_we/ram_addr/ram_wdata
  ▼
C RAM
  │ c_wr_pulse
  ▼
done_ctrl -> core_done -> start_ctrl DONE
```

## 5. 控制流向

```text
CPU 写 CTRL.start
  -> control_regs.start_req
  -> start_ctrl.start_pulse
  -> npu_ctrl.systolic_fsm
  -> config check
  -> tile_scheduler 初始化
  -> 预取 / 喂数 / 排空 / 收集
  -> K-tile 累加或 C 写回
  -> done_ctrl 统计实际 C RAM 写入
  -> core_done
```

关键完成语义：

```text
collect_done：当前 4x4 Tile 的 16 个结果已经输出
array_done：  直接等于 collect_done
write_done：  当前输出 Tile 的 C 写 FIFO 已排空
c_wr_pulse：  一笔数据真正写入 C RAM
core_done：   整个 M×N 输出全部写入 C RAM
```

## 6. v2.0 验证结果

使用 `python3 scripts/run_npu.py`，Icarus Verilog 仿真结果：

```text
T1~T5：功能、边界、量化和多 K-tile 场景全部 PASS
T6~T10：尺寸、Tile、容量和 TK 错误路径全部 PASS
结果：PASS=10 FAIL=0
```

v2.0 直接移除了 `mac_status` 的额外一拍，因此测试周期相较旧版本减少，但矩阵结果、MMIO 接口和错误码保持一致。
