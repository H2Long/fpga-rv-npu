# v2.1：控制平面与结果通路重构

版本：`v2.1`  
范围：`rtl/`、`tb/`、设计说明、地址与寄存器表、波形调试说明

## 1. 版本目标

v2.0 解决了"功能能不能跑通"，但阵列利用率只有 5%~18%，瓶颈不在 MAC，而在控制平面和结果通路：

- 每个 K Tile 都要清一次 PE 累加器、排空一次阵列，部分和被搬到阵列外再累加；
- 16 个结果被压成 32 位串行扫出（一次 16 拍），再在外部寄存器堆里重新攒起来；
- 预取阶段与喂数阶段互斥，预取延迟完全暴露；
- 写回期间状态机原地等待，阵列空转。

v2.1 只改微架构、不改数据通路：**把"每个 K Tile 停一次"改成"只在输出 Tile 边界停一次"，
结果改成快照 + 后台并行写回**。

## 2. 模块变化

| v2.0 模块 | v2.1 处理方式 | 原因 |
|---|---|---|
| `c_tile_acc_ctrl` | **删除** | 累加回到 PE 内部，阵列外不再需要第二份部分和寄存器堆 |
| `tile_result_collector` | **删除** | 结果不再串行扫出，快照直接进写回扫描器 |
| `input_unpacker` | **合并进 `npu_mac`** | 只被 MAC 平面使用的纯组合拆包，不值得独立层级 |
| `systolic_fsm` | **重写** | 13 状态（含 K 循环绕行）→ 7 状态；删除从未进入的 `S_CHECK_CONFIG` 和悬空端口 `first_k_tile` |
| `npu_stream_ctrl` | **重写** | 电平 `go` → 单拍启动、自动结束的读突发，支持预取与喂数重叠 |
| `c_tile_write_ctrl` | **重写** | 增加结果快照（累加器 + C 基地址 + 边界尺寸一起锁存），不再需要 `write_go` 状态 |
| `c_write_fifo` | **扩展** | `accumulate=1` 时做 C RAM 读-改-写，实现跨任务累加 |
| `start_ctrl` | **扩展** | 增加启动前配置校验和 `ERROR` 状态；`DONE=1` 时也接受新的 `start` |
| `control_regs` | **扩展** | 新增 `ACC_CFG`（0x10）的 `accumulate` 位 |
| `pe_array` | **重写** | 16 段手写例化 → `generate` 循环，`NPU_P/NPU_Q` 真正生效 |
| `drain_controller` | **简化** | 去掉复位输入，改为"`drain_en=0` 自动复位"，计数器位宽由 `P+Q-2` 推出 |
| `mmio_if` | **修正** | 保留地址按 `sel_status` 判定后读回 0（原来任意未映射地址都返回状态寄存器） |

模块数：28 → 20 个 `.v`。

## 3. 信号变化

| 变化 | 说明 |
|---|---|
| 删除 `array_start` | 阵列启动脉冲与"清累加器"合并为每个输出 Tile 一次的 `acc_clear` |
| 删除 `collect_done` / `c_result*` / `write_go` / `write_done` / `acc_rd_idx` | 串行结果收集通路整体移除 |
| 新增 `acc_flat_in[511:0]` | npu_mac → c_tile_write_ctrl 的 16 个累加器快照源 |
| 新增 `drain_done` | npu_mac → FSM（排空完成）与 c_tile_write_ctrl（快照触发） |
| 新增 `pf_start` / `pf_next_start` | 当前 K Tile 与下一个 K Tile 的预取突发启动脉冲 |
| 新增 `cwr_idle` | 写回通路空闲，FSM 用它保证快照不被覆盖，并参与 `core_done` |
| 新增 `STATUS.ERROR`(bit4) / `ACC_CFG`(0x10) | 配置错误上报与跨任务累加 |
| `NPU_FIFO_AW` 5 → 6 | A/BT 预取 FIFO 深度 64，覆盖"当前 K Tile + 下一个 K Tile"的峰值占用 32 |
| 新增 `NPU_CWF_AW` | C 写 FIFO 深度 32（一个 C Tile 最多 16 项） |
| `pe_array` / `drain_controller` 参数化 | `NPU_P`/`NPU_Q` 从装饰宏变成真正生效的规模参数 |

## 4. 数据流向变化

```text
v2.0：PE 累加器 → 串行扫出 16 拍 → c_tile_acc_ctrl 寄存器堆 → 再读出
      → 量化 → c_tile_write_ctrl → C 写 FIFO → C RAM（写回期间状态机等待）

v2.1：PE 累加器（跨 K Tile 连续累加）
      → 排空完成那一拍整块快照到 c_tile_write_ctrl
      → 扫描 16 lane 并量化 → C 写 FIFO → C RAM（与下一个 Tile 计算并行）
```

## 5. v2.1 验证结果

`tb/tb_npu.v` 扩展到 19 项用例，`PASS=19 FAIL=0`：

| 用例 | 结果 |
|---|---|
| G1 4×4×4 | PASS，48 周期 |
| G2 16×16×16 TK=4 | PASS，956 周期（v2.0：3031 周期）|
| G3 6×7×9 TK=3 | PASS，200 周期 |
| G4 5×5×6 TK=3 | PASS，176 周期 |
| G5 8×8×8 q=2 | PASS，196 周期 |
| G6 8×8×10 TK=4 q=3 | PASS（K 非 TK 整数倍 + 量化）|
| G7 8×8×16 TK=4 q=4 | PASS（多 K Tile + 量化）|
| G8 8×7×7 TK=1 | PASS（最小 K Tile）|
| G9 TK=1/2/4/8/16 | PASS，五种 TK 结果逐位一致 |
| GA 两段 K=8 累加 | PASS，等于单次 K=16 |

实测阵列利用率：4×4×4 为 8%，16×16×16 为 26%，8×8×32 为 35%~38%
（v2.0 对应为 5%、8%、8%）。

## 6. 本轮踩到的坑（已写进设计说明 §9）

1. 电平型状态机输出（`acc_clear`）忘记列进块首默认清零 → 永久保持，累加器每拍清零；
2. `S_DRAIN` 结束漏发 `next_out_req` → 输出 Tile 永不前进；
3. 快照只锁存累加器、没锁存 C 基地址和边界尺寸 → 写回扫描期间 tile 已前进，整块写错地址；
4. 跨任务累加放在 PE 累加器里是错的——16 个累加器被所有输出 Tile 复用，
   任务结束时保存的是最后一块的部分和；最终改为 C 写回路径读-改-写；
5. Verilog-2001 不允许实例输出直接驱动 `reg`，所以"内部 wire + `always @(*)` 转发到
   `output reg`"的写法是编码规范的必然结果，不是冗余包装。

# NPU v2.0 版本更新说明

版本：`v2.0`  
日期：`2026-09-30`  
范围：`rtl/`、设计说明、波形调试说明和架构绘图脚本

当前 v2.0 最终约束：`M/N/K` 可配置，`TM=TN=4` 固定，`TK` 可配置；保留 M/N 边界 Tile、多个 K Tile 部分和累加、量化和 C 写回。详细错误分类和错误码路径已删除。

## 1. 版本目标

v2.0 面向课程设计和后续迭代，重点是减少重复包装层、缩短控制信号路径、提高 A/BT/C 通道的复用率。计算功能、MMIO 地址映射和顶层 CPU 接口保持不变。

本版本的结构原则是：

```text
有独立时序或握手协议的模块保留；
纯组合译码、同构包装和恒等映射直接合并到所属功能平面。
```

## 2. 模块变化

### 2.1 顶层控制平面

| v1.x 模块 | v2.0 处理方式 | 变化原因 |
|---|---|---|
| `addr_decoder` | 合并到 `npu_top` | 纯组合地址译码，不需要独立层级 |
| `status_regs` | 合并到 `npu_top` | 只有一个状态读数据 mux |
| `cpu_port_ctrl` | 合并到 `buffer_access_ctrl` | 仲裁、地址、字节屏蔽和 RAM 端口一次完成 |
| `mmio_if` | 保留 | 保存请求生命周期和同步 RAM 读等待状态 |
| `control_regs` | 保留 | 保存软件配置和命令寄存器 |
| `start_ctrl` | 保留 | 保存任务生命周期和参数快照 |

当前 `npu_top` 的控制层为：

```text
mmio_if
control_regs
start_ctrl
buffer_access_ctrl
内联：地址译码、状态读回
```

### 2.2 调度与控制平面

| v1.x 模块 | v2.0 处理方式 | 变化原因 |
|---|---|---|
| `tile_param_latch` | 合并到 `tile_controller` 参数复用 | `start_ctrl` 已经锁存任务参数，避免重复寄存器 |
| `config_checker` | 删除 | 软件保证配置合法，减少错误分类逻辑 |
| `loop_counters_tile_status` | 合并到 `tile_controller` | Tile 数量、边界尺寸直接在调度中心派生 |
| `block_addr_gen` | 合并到 `tile_controller` | A/BT/C 地址与 Tile 状态天然相关 |
| `array_ctrl` | 合并到 `tile_controller` | 只是 FSM 阶段信号的组合译码 |
| `a_stream_ctrl`、`bt_stream_ctrl` | 直接复用两个 `npu_stream_ctrl` 实例 | 两个通道的逻辑完全相同 |
| `systolic_fsm` | 保留 | 负责完整计算阶段状态转移 |
| `c_tile_acc_ctrl` | 保留 | 负责多 K-tile 部分和累加 |
| `c_tile_write_ctrl` | 保留 | 负责边界过滤、C 地址和写请求 |
| `tile_controller` 内部逻辑 | 保留 | Tile 循环、A/BT 成对出队和 C 写入计数 |

### 2.3 Buffer 与搬运平面

| v1.x 模块 | v2.0 处理方式 | 变化原因 |
|---|---|---|
| `a_buffer`、`bt_buffer`、`c_buffer` | `npu_buffer` 直接实例化 `npu_ram` | 三块存储只有地址宽度不同 |
| `a_prefetch_fifo`、`bt_prefetch_fifo` | `npu_buffer` 直接实例化 `npu_sync_fifo` | 两个 FIFO 数据宽度和行为相同 |
| `npu_read_port_ctrl` | 内联到 `npu_buffer` | 只保存 A/BT 读使能的一拍延迟 |
| `c_write_fifo` | 保留 | 除 FIFO 外还负责 C RAM 写脉冲和 `c_wr_pulse` |

### 2.4 MAC 平面

| v1.x 模块 | v2.0 处理方式 | 变化原因 |
|---|---|---|
| `a_input_unpacker`、`bt_input_unpacker` | 合并为通用 `input_unpacker` | A 和 BT 的拆包、补零规则相同 |
| `output_reorder` | 删除，`scan_index` 直接作为结果索引 | 当前 collector 已按行主序扫描 |
| `mac_status` | 删除，`collect_done` 直接送入调度 FSM | 原模块只有一拍直通寄存器 |
| `a_bt_skew_pipeline` | 保留 | 负责行/列波前延迟 |
| `pe_array`、`pe_cell` | 保留 | 构成实际 4x4 脉动计算阵列 |
| `drain_controller` | 保留 | 负责阵列排空计数 |
| `tile_result_collector` | 保留 | 串行输出 16 个 PE 累加结果 |
| `result_quantizer` | 保留 | 负责右移、舍入和饱和 |

## 3. 信号线变化

v2.0 同时将 `npu_top` 的 MMIO 窗口译码收紧为明确的寄存器和 Buffer 范围，避免高地址别名：状态窗口为 `0x0020~0x002F`，A/BT/C 窗口分别为 `0x1000~0x10FF`、`0x2000~0x20FF`、`0x3000~0x33FF`。

### 3.1 保持不变的外部接口

`npu_system` 的 CPU 接口保持不变：

```text
clk, rst
cpu_addr[31:0], cpu_wdata[31:0], cpu_byte_en[3:0]
cpu_we, cpu_valid, cpu_rdata[31:0], cpu_ready
```

`npu_top` 与 `tile_controller` 的任务级接口保持相同语义：

```text
start_pulse
cfg_m/cfg_n/cfg_k
cfg_tm/cfg_tn/cfg_tk/cfg_qshift
core_busy/core_done
```

`tile_controller`、`npu_buffer`、`npu_mac` 之间的主数据接口按固定 4x4 Tile 简化。

### 3.2 删除的信号

```text
feed_last
```

`feed_last` 原来由 `systolic_fsm` 产生，但 `array_ctrl` 不使用它；排空实际由 `drain_en` 控制。

结果索引和完成信号现在直接连接：

```text
c_result_index = scan_index
collect_done   -> systolic_fsm
```

```text
cpu_buf_wdata
cpu_buf_byte_en
ram_a_*
ram_bt_*
ram_c_*
```

这些中间线由 `buffer_access_ctrl` 合并为直接输出：

```text
cpu_a_addr/cpu_a_we/cpu_a_re/cpu_a_wdata
cpu_bt_addr/cpu_bt_we/cpu_bt_re/cpu_bt_wdata
cpu_c_addr/cpu_c_we/cpu_c_re/cpu_c_wdata
```

### 3.3 本轮进一步收缩

在保留 M/N/K、边界 Tile、TK 分块和量化功能的前提下，又删除了以下重复线：

```text
array_clear_acc       由 array_start 直接驱动 PE 清零
a_stream_ready        当前无独立反压，删除
bt_stream_ready       当前无独立反压，删除
a_stream_valid        A/BT 共用 stream_valid
bt_stream_valid       A/BT 共用 stream_valid
a_fifo_valid          由 a_fifo_count != 0 判断
bt_fifo_valid         由 bt_fifo_count != 0 判断
buffer_ready          由 !core_busy 直接生成 STATUS.bit3
array_flush           统一命名为 drain_en
array_done             统一使用 collect_done
```

新的 MAC 输入接口为：

```text
stream_valid
a_stream_data
bt_stream_data
a_lane_en
bt_lane_en
```

tile_controller 只有在 `feed_go=1` 且 A/BT 两侧 FIFO count 都非零时产生 `pair_fire`，并用同一个 `stream_valid` 同拍驱动两个输入拆包器。

FIFO 两侧使用一条 `fifo_pair_pop` 同时出队；`busy_status` 由 `tile_controller.core_busy` 统一提供；MMIO 的 Buffer 等待条件直接在 `mmio_if` 内由三类窗口选择信号判断。

### 3.4 新的内部信号归属

同步 RAM 读延迟现在属于 `npu_buffer`：

```text
npu_a_re  -> a_re_d  -> a_fifo_push
npu_bt_re -> bt_re_d -> bt_fifo_push
```

这样 RAM、读延迟和预取 FIFO 在同一模块内完成，数据有效时序更容易追踪。

## 4. 当前数据流向

### 4.1 CPU 装载数据

```text
CPU MMIO
  │ cpu_addr/cpu_wdata/cpu_we/cpu_valid
  ▼
mmio_if
  │ req_addr/req_wdata/req_we/req_valid
  ▼
npu_top 内联译码
  ├── 控制窗口 -> control_regs
  ├── 状态窗口 -> status_rdata
  └── Buffer窗口 -> buffer_access_ctrl
                         │ 地址/读写/字节屏蔽
                         ▼
                      npu_buffer
                         ├── A RAM
                         ├── BT RAM
                         └── C RAM
```

### 4.2 A/BT 输入数据

```text
tile_controller 内部 Tile 循环和地址计算
  │ a_addr/a_re, bt_addr/bt_re
  ▼
npu_buffer.npu_ram
  │ 同步 RAM 数据
  ▼
npu_buffer 内部读延迟
  │ a_fifo_push/bt_fifo_push
  ▼
A/BT npu_sync_fifo
  │ a_fifo_rdata/count
  │ bt_fifo_rdata/count
  ▼
tile_controller 成对出队
  │ a_stream_data + bt_stream_data
  │ pair_fire
  ▼
npu_mac
```

### 4.3 MAC 计算数据

```text
32 位 A/BT 字
  ▼
input_unpacker(A/BT)
  │ 4 个 INT8 lane + lane valid
  ▼
a_bt_skew_pipeline
  │ 行/列波前对齐
  ▼
4x4 pe_array
  │ 每个 PE 累加 32 位部分和
  ▼
drain_controller + tile_result_collector
  │ c_result/c_result_index/c_result_valid
  ▼
c_tile_acc_ctrl
  │ 首个 K-tile 装入，后续 K-tile 累加
  ▼
result_quantizer
```

### 4.4 C 写回数据

```text
c_tile_write_ctrl
  │ cwr_valid/cwr_addr/cwr_data
  ▼
c_write_fifo
  │ ram_we/ram_addr/ram_wdata
  ▼
C RAM
  │ c_wr_pulse
  ▼
tile_controller 完成计数 -> core_done -> start_ctrl DONE
```

## 5. 控制流向

```text
CPU 写 CTRL.start
  -> control_regs.start_req
  -> start_ctrl.start_pulse
  -> tile_controller.systolic_fsm
  -> config check
  -> tile_controller 初始化
  -> 预取 / 喂数 / 排空 / 收集
  -> K-tile 累加或 C 写回
  -> tile_controller 统计实际 C RAM 写入
  -> core_done
```

关键完成语义：

```text
collect_done：当前 4x4 Tile 的 16 个结果已经输出
collect_done：当前 4x4 Tile 的 16 个结果已经输出
write_done：  当前输出 Tile 的 C 写 FIFO 已排空
c_wr_pulse：  一笔数据真正写入 C RAM
core_done：   整个 M×N 输出全部写入 C RAM
```
