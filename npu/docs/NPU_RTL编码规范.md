# NPU RTL 编码规范

本规范用于 `npu/rtl` 下的 Verilog-2001 RTL。代码风格参考 `project_risc_v/core`
中的模块：先说明接口和时序，再按“组合判据、寄存器、输出”组织实现。

## 文件与模块

- 每个文件只实现一个主要模块，文件名与模块名一致。
- 文件顶部先写模块职责、数据布局、时序延迟和端口所有权，再写 `include` 与模块声明。
- 统一使用 Verilog-2001 语法：`always @(posedge clk or negedge rst_n)` 用于时序逻辑，
  `always @(*)` 用于组合逻辑。
- 时序逻辑使用非阻塞赋值 `<=`；组合逻辑使用阻塞赋值 `=`；连续连线使用 `assign`。
- 参数使用大写或项目已有宏，状态常量使用 `S_`、`C_`、`ST_` 前缀。

## 端口和信号

- 端口一行一个声明，宽度写在信号名前：`input wire [31:0] data`。
- 同一时钟域的 valid、ready、data 必须说明采样沿和保持周期。
- `*_valid` 表示当前拍数据/请求有效；`*_ready` 表示接收方当前拍可以接收；
  `fire` 或 `*_fire` 表示 valid 与 ready 同时成立并真正发生传输。
- `*_q`、`*_d` 分别表示寄存值和一拍延迟值；`*_rdata` 表示读数据，不能与请求 valid 脱离说明。
- 内部组合信号先声明，随后用 `assign` 或 `always @(*)` 完整赋值，避免隐含锁存器。

## 时序逻辑

- 异步低有效复位统一写成 `or negedge rst_n`，复位分支必须为所有状态寄存器提供确定值。
- 一个时序块中先写复位，再写默认脉冲清零，最后写状态分支。
- 单拍脉冲在每个时钟沿默认清零，只在产生事件的分支拉高。
- 状态机的状态转移、状态输出和计数器更新放在同一个时钟域中，并在状态定义旁说明每个状态的入口、
  保持条件和退出条件。

## 存储器和 FIFO

- 同步 RAM 必须说明“请求沿”和“数据返回沿”的关系；读请求 valid 要与返回数据延迟相同。
- FIFO 的 `push`、`pop` 必须分别受 `full`、`empty` 门控；同时 push/pop 时明确 count 是否变化。
- Buffer 地址统一说明是字节地址还是 32 位字地址。MMIO 层负责 `(addr - base) >> 2` 转换。

## 注释要求

每个功能模块至少说明：

1. 模块在系统中的位置和职责；
2. 输入/输出数据的布局和单位；
3. valid/ready 或 RAM 的时序延迟；
4. 复位后的状态以及状态机的主要转移；
5. 边界条件、错误处理和不能修改的接口假设。

注释解释“为什么这样写”，而不是重复代码字面含义。例如需要说明为什么 `c_wr_pulse` 必须统计
C RAM 的实际写入，而不能统计 C 写 FIFO 的入队。
